# Технологический радар «Будущего 2.0»

Начальный срез отражает роль технологии внутри компании к началу программы. Банковские сервисы на Go и Java и сервисы ИИ на Python уже действуют. SQL Server 2008, PowerBuilder, Apache Camel и кастомный Power BI обеспечивают работу старых процессов на время перехода. Целевой стек описан в [Task3](../Task3Advanced/architecture.md), а правила владения событиями и их потребления — в [Task4](../Task4Advanced/events.md).

**Adopt** — применять в указанной области с действующим владельцем и поддержкой. **Trial** — ограниченное испытание с воспроизводимой проверкой. **Assess** — изучить на согласованном сценарии и принять решение о пилоте. **Hold** — сопровождать действующую зависимость до переключения и ограничить её расширение. В последней колонке указаны ориентиры от старта программы. Переход в следующее кольцо требует выполнения критерия. [Методика внутреннего радара Thoughtworks](https://www.thoughtworks.com/content/dam/thoughtworks/documents/report/thoughtworks-enterprise-architecture-playbook.pdf)

## Жизненный цикл решений

Совет доменов пересматривает радар раз в квартал и перед каждой новой [волной роадмапа](roadmap.md). Для позиции владелец предъявляет протокол испытания, рабочие границы, затраты эксплуатации и способ отката. При смене версии или региона повторяются затронутые тесты совместимости и доступа. Для Hold владелец ведёт список оставшихся потребителей, дату отключения и условия чтения архива. Исключения оформляются с датой пересмотра. Предварительные сроки обновляют по результатам сверки, измерениям SLO и фактическому TCO.
